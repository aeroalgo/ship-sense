## 2. Суть продукта (согласованное понимание)

- Это **не замена АПС** и не SCADA в контуре управления.  
- АПС даёт «сейчас» и тревоги; **историю не хранит**.  
- ShipSense **только читает** АПС, копит историю годами, показывает тренды, журнал, вахтенные сводки, отчёты.  
- Юридически важно: **вне контура**, доказуемый **read-only** (I1).  
- Объём сигналов: **~586** (АПС ~482 + СКТ ГЭУ ~104), опрос порядка **1 Гц**.  
- Два потока: **телеметрия** (ряды) и **события** (append-only).  
- Edge на судне **автономен** без спутника/берега.

### Три боли

1. Смена экипажа — «что было на вахте».  
2. Ручной документооборот стармеха.  
3. Износ замечают поздно — тренды и дрейф к уставке.

## 7. Принятые решения по инфраструктуре

Зафиксированы в `memory-bank/systemPatterns.md` и `techContext.md`.

| Тема | Решение |
|------|---------|
| Стек backend | Python 3.12+, FastAPI, asyncio, Pydantic v2 |
| БД edge | PostgreSQL + TimescaleDB (`samples` hypertable + `events`) |
| Hot path | **asyncio.Queue внутри collector**; IPC → процесс **writer**; **api** отдельно. Redis/Kafka нет |
| Frontend | Next.js App Router, React, TypeScript; WS realtime |
| Деплой | Docker Compose (`emulator`, `db`, `collector`, `writer`, `api`, `web`) |
| Протоколы АПС | Плагины B2 и B3 через B1; боевой — по Q1 |
| Изоляция источников | Supervised asyncio tasks **внутри collector**; process-per-source — эскалация после soak |
| Берег БД | Postgres для MVP v2; **ClickHouse не нужен** на старте |
| Досыл | **Cursor** + сборка батча при связи; опционально `outbox_batches` |
| Не делать | Полный per-event outbox (раздувает диск) |
| Транспорт берег | HTTPS POST с судна, **ACK**; файлы — только fallback |
| На берег | События + агрегаты; **сырой 1 Гц остаётся на судне** |
| Observability | С **v1**: логи, snapshots диска/RAM/CPU, алерт ≥80% диска |

### Объём данных (оценка)

- ~586 × 1 Гц × год ≈ **18,5 млрд** точек.  
- На диске со сжатием Timescale ориентир **~0,1–0,3 ТБ/год**; без сжатия до ~1 ТБ.  
- Очередь досыла на берег — на порядки меньше архива.

### Cursor vs статусы

- Отдельная таблица **delivery_cursor** (1–2 строки на поток).  
- На каждом событии статус `pending/sent` **не обязателен**.  
- ACK берега двигает курсор; повтор батча безопасен через idempotency_key.

## 8. Досыл на берег — выводы из обсуждения

- Это **не** «набросать forwarder за вечер»: нужны канал (Q7), профиль обрывов, лимиты батчей, ёмкость берега на N судов.  
- Пока связи нет: архив пишется дальше; forwarder ждёт; нужен мониторинг ПК (логи/снимки), иначе не видно распухания диска.  
- Дублировать весь архив в outbox «на всякий случай» **не нужно**.  
- Research track описан в `plan-v2-shore.md` → будущий `research-v2-shore-link.md`.

Текст пользователя из переписки (суть): куча вопросов по связи/лимитам — исследовательская работа; нужны логи и снимки системных параметров ПК.

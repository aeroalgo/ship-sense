# Карточка «Не паниковать»: stale и quarantine

## Как читать состояние

| Индикатор | Что он значит | Что делать |
|---|---|---|
| Свежий sample | sample пришёл в ожидаемом окне и прошёл policy | читать значение вместе с timestamp и единицей |
| `stale` | новый sample не пришёл вовремя | сообщить, записать время/tag, не считать свежим |
| `quarantine` | sample нарушил policy или не прошёл проверку | не использовать как нормальное значение, открыть discrepancy |
| `unknown/null` | достоверного значения нет | применить approved ship procedure, не угадывать |

Цвет сам по себе не является доказательством. Всегда проверить banner, timestamp, tag id и source.

## Алгоритм экипажа

1. Остановиться и прочитать полное сообщение состояния.
2. Записать UTC-время, экран, tag id/KKS, показанное значение и timestamp последнего sample.
3. Сделать screenshot без секретов и приложить его к журналу.
4. Спросить старшего механика, требуется ли approved fallback для судна.
5. Открыть discrepancy/incident с владельцем и приоритетом.
6. Если состояние связано с storage, gateway, write reject или потерей архива — вызвать ответственного инженера.
7. После восстановления проверить **новый** sample и закрыть incident только с evidence.

## Запрещено

- Не подменять stale значением «на глаз».
- Не считать предыдущий sample свежим.
- Не отключать quarantine policy.
- Не отправлять write-запрос в АПС для проверки.
- Не удалять stale banner, log или screenshot.
- Не запускать OTA, пока данные/health не объяснены и нет разрешённого окна.

## Быстрый escalation

| Событие | Кому сообщить | P1? |
|---|---|---|
| один некритичный stale tag | старший механик | нет, записать |
| несколько критических stale tags | старший механик + инженер edge | да, оценить немедленно |
| quarantine на критическом tag | старший механик + интегратор | да, не использовать значение |
| archive/storage error | ответственный инженер | да |
| неожиданный write/потеря read-only | I4 lead / интегратор | немедленный no-go |

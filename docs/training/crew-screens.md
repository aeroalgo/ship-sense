# Карточка обучения: экраны 1–10 по ролям

## Цель

За 2 часа hands-on научить вахтенных и старшего механика находить рабочий экран, читать состояние данных и не принимать stale или quarantine за свежий измерительный сигнал. Все действия выполняются через read-only интерфейс.

## Правила перед началом

- Не вводить и не искать пароли в скриншотах или evidence.
- Не использовать экран как доказательство свежести без проверки timestamp и banner.
- `stale` означает, что новый sample не пришёл в ожидаемое окно.
- `quarantine` означает, что значение не прошло policy и не должно использоваться как нормальное измерение.
- `unknown/null` не заменять последним значением вручную.
- Запись в АПС запрещена; write-path проверяется по `docs/acceptance/T4-readonly-protocol.md`.

## Упражнения

### Упражнение A — найти свежий сигнал

1. Открыть экран 2 и выбрать согласованный критический tag.
2. Назвать значение, единицу, источник и timestamp.
3. Перейти на экран 3 и подтвердить, что trend использует тот же tag id.
4. Если timestamp старше ожидаемого окна, показать stale banner и не объявлять значение свежим.

1. Открыть экран 7 и выбрать контролируемый quarantined tag.

3. Подтвердить, что прошлое нормальное значение не выдано как текущее.

## Что делать при неправильном состоянии

| Состояние | Действие экипажа | Запрещено |
|---|---|---|
| `stale` | сообщить старшему механику, записать время и tag | считать последним значением свежим |
| `quarantine` | сохранить evidence, открыть discrepancy, эскалировать | обходить policy или вручную подставлять число |
| `unknown/null` | использовать approved fallback procedure судна | угадывать значение |
| degraded storage | прекратить необязательные операции, вызвать ответственного | извлекать диск без A4 procedure |
| OTA pending | проверить anchorage/maintenance window | подтверждать update в рейсе |
| T4 write reject | считать gateway защитным gate, приложить log | повторять write вне test window |
